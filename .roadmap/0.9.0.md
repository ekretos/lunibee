# Lunibee 0.9.x — API freeze (release-candidate line)

**Theme:** decide what 1.0 promises. After 0.9.0 the public API only changes to
fix bugs found by early adopters; every 0.9.x release is a 1.0 candidate.

**Target:** 0.9.0, then 0.9.x bug-fix releases. Branch: `dev`.

**Principle:** nothing new. Mark, rename once, document, measure, audit.

---

## Step 1 — Mark the surface

1. [ ] Every export of `lunibee` and the `@lunibee/*` packages is public, `@internal` or
   `@experimental`.
2. [ ] The API audit fails on an unmarked export and on removing or changing a public one; its
   snapshot becomes the 1.0 baseline.

## Step 2 — Names 1.x would regret

1. [ ] Resolve duplicate names (`send` / `sendMessage`, `edit` / `update` and the like): keep one,
   deprecate the other with a one-time runtime warning, removal in 2.0.
2. [ ] The naming convention (`CreateX`, `…Enum`, `…Type` for styles) holds for every constant set.

## Step 3 — Documentation

1. [ ] Every public class and function has a reference page and a runnable example; generated API
   docs build without warnings.
2. [ ] Upgrade guide from 0.4.x to 1.0 with every breaking change and its fix; `lunibee migrate`
   covers what can be rewritten.
3. [ ] Semver and deprecation policy published in the README and docs.

## Step 4 — The sample bot

1. [ ] `examples/complete-bot` (started in 0.5.0): slash, prefix and context-menu commands,
   components, moderation, sharding, voice; runs in CI against the fake Discord servers.

## Step 5 — Security review

1. [ ] Token handling and redaction in errors, logs and telemetry; input limits in builders;
   path, header and query handling in REST; dependency and supply-chain audit.
2. [ ] Findings classified P0–P3 (AGENT.md); P0/P1 fixed before 1.0.

## Step 6 — Early adopters

1. [ ] At least one production bot (ZedBot) runs 0.9.x; its issues are fixed in 0.9.x releases.
2. [ ] 0.9.x releases contain bug fixes only.

## Release checklist

- [ ] Root and workspace package versions correct (0.9.0)
- [ ] Changelog and upgrade guide updated
- [ ] P0/P1 resolved and verified; P2/P3 resolved or tracked
- [ ] `check:deps`, API audit (baseline frozen), prettier, typecheck, tests + coverage, `check:leaks`
- [ ] Production build, DTS build, docs build, generated API docs, every example runs in CI
- [ ] Final smoke test: `examples/complete-bot` against a real test guild
