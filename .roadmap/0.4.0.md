# Lunibee 0.4.x — voice that plays audio

**Theme:** `@lunibee/voice` today models connections but cannot carry audio
(docs/audits/voice-report.md): no voice handshake, `setSpeaking` sends `ssrc: 0`,
no encryption, no Opus, and the player busy-polls while paused. 0.4.0 makes a
bot able to join a channel and play a file or stream, end to end.

**Target:** 0.4.0, then 0.4.x patches. Branch: `dev`.

**Non-goals:** video/Go Live, DAVE end-to-end encryption before Discord requires
it for bots (tracked), recording as a first-class feature (receive stays low-level).

**If this slips:** voice is marked `@experimental` at 1.0; nothing else waits for it.

---

## Step 1 — Client-side join and leave

1. [ ] `client.voice.join({ guildId, channelId, selfDeaf, selfMute })` sends op 4 (Voice State
   Update) through the shard that owns the guild.
2. [ ] Collect the bot's own `VOICE_STATE_UPDATE` (session id) and `VOICE_SERVER_UPDATE`
   (token, endpoint) in `core`, with a timeout, and hand them to the voice connection.
3. [ ] `connection.disconnect()` / `client.voice.leave(guildId)` sends op 4 with `channel_id: null`.
4. [ ] Handle moves (channel changed by a moderator) and region changes (new server update).
5. [ ] Tests with a fake Gateway emitting both events in either order; timeout path.

## Step 2 — Voice Gateway handshake

1. [ ] Voice WebSocket (v8): IDENTIFY (op 0) → READY (op 2: ssrc, ip, port, modes) →
   SELECT_PROTOCOL (op 1) → SESSION_DESCRIPTION (op 4: mode, secret key).
2. [ ] Heartbeat with `seq_ack` (op 3/6), RESUME (op 7) on recoverable closes, close-code table
   (4006/4014 not resumable; 4015 resume).
3. [ ] Store the negotiated SSRC; `setSpeaking` uses it (fixes finding 1).
4. [ ] Reuse `ws` package seams (transport, heartbeat, reconnect) rather than a second stack.
5. [ ] Tests from recorded voice-gateway frames.

## Step 3 — UDP and IP discovery

1. [ ] Bun UDP socket (`Bun.udpSocket`) to the READY endpoint.
2. [ ] IP discovery packet (type 0x1, length 70) and response parsing.
3. [ ] Keepalive, socket close on disconnect, no leaked sockets (tests assert close).

## Step 4 — Transport encryption

1. [ ] Implement Discord's current AEAD modes: `aead_aes256_gcm_rtpsize` (preferred when
   available) and `aead_xchacha20_poly1305_rtpsize` (required fallback).
2. [ ] Use WebCrypto for AES-GCM; XChaCha20-Poly1305 via a small audited dependency
   (e.g. `@noble/ciphers`) — dependency choice recorded with reasons.
3. [ ] RTP header (version, payload type 0x78, sequence, timestamp, SSRC), nonce handling per mode.
4. [ ] Test vectors for both modes; sequence/timestamp wraparound tests.

## Step 5 — Opus

1. [ ] Decide native vs WASM by benchmark (encode 20 ms frames at 48 kHz stereo; CPU per stream).
2. [ ] Optional peer dependency so bots without voice do not install it.
3. [ ] Encoder and decoder wrappers with explicit `destroy()`; bounded frame buffers.
4. [ ] Tests: encode → decode round-trip of a known PCM sample within tolerance.

## Step 6 — Audio resources and the player

1. [ ] `createAudioResource(input)` from a file path, `ReadableStream`, `Buffer`, or Ogg/Opus
   (passthrough without re-encoding) and PCM s16le.
2. [ ] Optional FFmpeg integration for arbitrary formats (spawned process, killed on end/stop).
3. [ ] Replace the 25 ms busy poll with an event-driven pump (resume promise) — fixes finding 3.
4. [ ] 20 ms frame scheduler with drift correction; 5 silence frames on stop.
5. [ ] Player states `idle | buffering | playing | paused | autopaused`, events, `play/pause/
   unpause/stop`, volume (inline, optional).
6. [ ] `entersState(target, state, timeoutMs)` helper for discord.js familiarity.
7. [ ] Remove the redundant `assertUsable` indirection (finding 4).

## Step 7 — Receiving (low-level)

1. [ ] Decrypt incoming RTP, map SSRC → user via op 5 speaking events.
2. [ ] `receiver.subscribe(userId)` returns a stream of Opus packets; ends on silence timeout.
3. [ ] Bounded per-user buffers; unsubscribing releases them.

## Step 8 — Lifecycle and safety

1. [ ] One connection per guild; joining again moves it.
2. [ ] Cleanup on guild leave, shard destroy and client destroy (sockets, FFmpeg, timers).
3. [ ] Reconnect on voice server change without dropping the player; resume after network blip.
4. [ ] Memory test: 100 join/leave cycles with no growth in handles.

## Step 9 — End-to-end test and example

1. [ ] Recorded voice session (gateway frames + UDP packets) replayed in CI.
2. [ ] `examples/music`: join, play a file, queue, skip, leave, with slash commands.
3. [ ] Voice guide on the docs site; `VoiceConnection` / `AudioPlayer` reference.

## Step 10 — Release 0.4.0

1. [ ] Mark any unfinished part `@experimental` explicitly.
2. [ ] Release checklist below; tag; announcement.

## Tracked

- DAVE (end-to-end encrypted voice) — required by Discord on a published timeline; plan once
  the protocol is required for bots.
- Video / Go Live — not planned before 1.0.
