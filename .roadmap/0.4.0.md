# Lunibee 0.4.x — voice that plays audio

**Theme:** `@lunibee/voice` today models connections but cannot carry audio
(voice review): no voice handshake, `setSpeaking` sends `ssrc: 0`,
no encryption, no Opus, and the player busy-polls while paused. 0.4.0 makes a
bot able to join a channel and play a file or stream, end to end.

**Target:** 0.4.0, then 0.4.x patches. Branch: `v0.4`.

**Non-goals:** video/Go Live, recording as a first-class feature (receive stays low-level).
DAVE was a non-goal "before Discord requires it"; Discord has required it for every non-stage call
since 2026-03-01, so it is in 0.4.0 (optional peer `@snazzah/davey`, the library discord.js uses).

**Status (2026-10-16):** Steps 1–9 delivered on branch `v0.4`. Decisions:
- AES-GCM uses synchronous `node:crypto`, not WebCrypto (Step 4.2): WebCrypto is async and would
  add a promise per 20 ms packet. XChaCha20-Poly1305 uses `@noble/ciphers` (audited, pure JS, no deps).
- Opus (Step 5.1): measured encode of a 20 ms 48 kHz stereo frame: `opusscript` (WASM) 226 µs
  under Bun, `@discordjs/opus` (native) 183 µs under Node, but its prebuilt binary does not load
  under Bun (ABI mismatch). `createOpusCodec()` tries native, then `opusscript`; both optional peers.
- Step 2.5 / 9.1: "recorded" frames are a scripted fake voice server (`tests/helpers/fake-voice-server.ts`,
  WebSocket v8 + UDP + its own rtpsize crypto), not a capture of a real Discord session.

**If this slips:** voice is marked `@experimental` at 1.0; nothing else waits for it.

## Step 1 — Client-side join and leave

1. [x] `client.voice.join({ guildId, channelId, selfDeaf, selfMute })` sends op 4 (Voice State
   Update) through the shard that owns the guild.
2. [x] Collect the bot's own `VOICE_STATE_UPDATE` (session id) and `VOICE_SERVER_UPDATE`
   (token, endpoint) in `core`, with a timeout, and hand them to the voice connection.
3. [x] `connection.disconnect()` / `client.voice.leave(guildId)` sends op 4 with `channel_id: null`.
4. [x] Handle moves (channel changed by a moderator) and region changes (new server update).
5. [x] Tests with a fake Gateway emitting both events in either order; timeout path.

## Step 2 — Voice Gateway handshake

1. [x] Voice WebSocket (v8): IDENTIFY (op 0) → READY (op 2: ssrc, ip, port, modes) →
   SELECT_PROTOCOL (op 1) → SESSION_DESCRIPTION (op 4: mode, secret key).
2. [x] Heartbeat with `seq_ack` (op 3/6), RESUME (op 7) on recoverable closes, close-code table
   (4006/4014 not resumable; 4015 resume).
3. [x] Store the negotiated SSRC; `setSpeaking` uses it (fixes finding 1).
4. [x] Reuse `ws` package seams (transport, heartbeat, reconnect) rather than a second stack.
5. [x] Tests from recorded voice-gateway frames.

## Step 3 — UDP and IP discovery

1. [x] Bun UDP socket (`Bun.udpSocket`) to the READY endpoint.
2. [x] IP discovery packet (type 0x1, length 70) and response parsing.
3. [x] Keepalive, socket close on disconnect, no leaked sockets (tests assert close).

## Step 4 — Transport encryption

1. [x] Implement Discord's current AEAD modes: `aead_aes256_gcm_rtpsize` (preferred when
   available) and `aead_xchacha20_poly1305_rtpsize` (required fallback).
2. [x] Use WebCrypto for AES-GCM; XChaCha20-Poly1305 via a small audited dependency
   (e.g. `@noble/ciphers`) — dependency choice recorded with reasons.
3. [x] RTP header (version, payload type 0x78, sequence, timestamp, SSRC), nonce handling per mode.
4. [x] Test vectors for both modes; sequence/timestamp wraparound tests.

## Step 5 — Opus

1. [x] Decide native vs WASM by benchmark (encode 20 ms frames at 48 kHz stereo; CPU per stream).
2. [x] Optional peer dependency so bots without voice do not install it.
3. [x] Encoder and decoder wrappers with explicit `destroy()`; bounded frame buffers.
4. [x] Tests: encode → decode round-trip of a known PCM sample within tolerance.

## Step 6 — Audio resources and the player

1. [x] `createAudioResource(input)` from a file path, `ReadableStream`, `Buffer`, or Ogg/Opus
   (passthrough without re-encoding) and PCM s16le.
2. [x] Optional FFmpeg integration for arbitrary formats (spawned process, killed on end/stop).
3. [x] Replace the 25 ms busy poll with an event-driven pump (resume promise) — fixes finding 3.
4. [x] 20 ms frame scheduler with drift correction; 5 silence frames on stop.
5. [x] Player states `idle | buffering | playing | paused | autopaused`, events, `play/pause/
   unpause/stop`, volume (inline, optional).
6. [x] `entersState(target, state, timeoutMs)` helper for discord.js familiarity.
7. [x] Remove the redundant `assertUsable` indirection (finding 4).

## Step 7 — Receiving (low-level)

1. [x] Decrypt incoming RTP, map SSRC → user via op 5 speaking events.
2. [x] `receiver.subscribe(userId)` returns a stream of Opus packets; ends on silence timeout.
3. [x] Bounded per-user buffers; unsubscribing releases them.

## Step 8 — Lifecycle and safety

1. [x] One connection per guild; joining again moves it.
2. [x] Cleanup on guild leave, shard destroy and client destroy (sockets, FFmpeg, timers).
3. [x] Reconnect on voice server change without dropping the player; resume after network blip.
4. [x] Memory test: 100 join/leave cycles with no growth in handles.
