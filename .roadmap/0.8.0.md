# Lunibee 0.8.x — scale and operations

**Theme:** what a large bot needs to run Lunibee for months: sharding that grows
without downtime, state that survives a restart, and the numbers to prove it.

**Target:** 0.8.0, then 0.8.x patches. Branch: `dev`.

**Principle:** opt-in, behind the current API. A single-process bot changes nothing.

---

## Step 1 — Resharding without downtime

1. [ ] `ClusterManager.reshard({ shardCount })`: start the new shard set alongside the old one,
   switch over when every new shard is ready, then stop the old set; IDENTIFY buckets respected
   throughout.
2. [ ] Optional automatic resharding from `/gateway/bot`'s recommendation, off by default.
3. [ ] Tests with the fake Gateway: no dispatch lost or duplicated across the switch.

## Step 2 — Sessions that survive a restart

1. [ ] Persist each shard's `session_id`, `resume_gateway_url` and sequence (pluggable store; Redis
   and file adapters), so a rolling deploy resumes instead of re-identifying.
2. [ ] Expired sessions fall back to IDENTIFY; tests for a resume after a process restart.

## Step 3 — Shared cache

1. [ ] `RedisCache` (0.3.2) out of `@experimental`: consistency rules documented (Gateway order
   wins, fetches never overwrite newer state), memory per guild measured.
2. [ ] Cache presets (`minimal`, `default`, `full`) with documented memory per guild at each.

## Step 4 — Observability, finished

1. [ ] One metrics surface across REST, Gateway, cache, sharding and voice (building on
   `RESTMetrics` and 0.5.0's metrics hooks); Prometheus and OpenTelemetry adapters.
2. [ ] Health endpoint helper for orchestrators (ready, live, degraded with the reason).

## Step 5 — Performance and soak testing

1. [ ] Publish benchmark results (`bun run bench`): Gateway dispatch throughput, REST scheduling,
   cache memory per guild; CI fails on a regression past a set margin.
2. [ ] A 24-hour soak test (fake Gateway at production event rates, reconnect storms, voice
   join/leave, cluster restarts) with `check:leaks` assertions at the end.

## Step 6 — Release 0.8.0

1. [ ] Operations guide: deploys, resharding, Redis, metrics, alerts.
2. [ ] Release checklist below; tag; announcement.

## Release checklist

- [ ] Root and workspace package versions correct (0.8.0)
- [ ] Changelog and upgrade guide updated
- [ ] P0/P1 resolved and verified; P2/P3 resolved or tracked
- [ ] `check:deps`, API audit, prettier, typecheck, tests + coverage, `check:leaks`
- [ ] Production build, DTS build, docs build, generated API docs
- [ ] Final smoke test: reshard a running test bot from 2 to 4 shards with no lost events
