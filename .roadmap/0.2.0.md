# Lunibee 0.2.x — friendlier API, new names, small fixes

**Theme:** make Lunibee pleasant for a real bot (ZedBot is the reference user)
without breaking anything. Every change in the line is additive; renamed APIs
keep their old names as deprecated aliases.

| Release | State | Branch |
|---|---|---|
| 0.2.0 | Released | `master` |
| 0.2.1 | Released (npm) | `master` |
| 0.2.2 | In progress | `dev` |
| 0.2.3 | Reserved for fixes found by early adopters | `dev` |

## 0.2.0 — released (record)

Foundation of the line: Gateway split into modules (session, heartbeat,
reconnect, transport, decoder, protocol), REST reservations and Redis store,
bounded message cache, Gateway cache sync for guilds/members/roles/emojis/
stickers/channels/threads/voice states, interaction acknowledgement guard,
follow-ups, modals and collectors. See the changelog on the docs site.

### Step 0 — P1: zombie reconnect loop (do first)

**Finding (P1, shard instability).** `GatewayHeartbeat.receivedMessage()` exists but the
Gateway never calls it: `Gateway.#message()` in `packages/ws/src/index.ts` records the
sequence and applies the frame, and nothing else resets the silence clock after
`watch()` on open. With the default `zombieTimeout: 30000`, every healthy connection is
declared a zombie once `stalenessDeadline` (≈ heartbeat interval + ACK budget, ~41–50 s)
passes, closed with the resumable code and reconnected — forever, on every shard. Each
cycle costs a RESUME (or an IDENTIFY when the resume fails) and emits a "zombie" event
plus a `GatewayError`. ZedBot works around it with `zombieTimeout: Infinity`
(`src/index.ts`), which disables the staleness watch entirely; dead sockets are then
only caught by the heartbeat ACK timeout.

1. [x] In `Gateway.#message()`, call `this.#heartbeat.receivedMessage()` for every frame the
   session owns, before classifying it (any inbound frame proves the socket is alive,
   including HEARTBEAT_ACK, DISPATCH, RECONNECT and INVALID_SESSION).
2. [x] Regression test in `tests/gateway.heartbeat.test.ts` / a Gateway test with a fake clock:
   steady inbound traffic for 5× `zombieTimeout` → no `zombie` event, no close; then silence
   past the deadline → exactly one `zombie` event and one resumable close.
3. [x] Test that a frame from a superseded socket (`!session.owns(token)`) does **not** reset
   the clock of the current one.
4. [x] Test the reconnect path: after a zombie close and RESUME, the clock is re-armed by
   `watch()` and reset by the first frame of the new socket.
5. [x] Audit the other liveness paths while here: heartbeat ACK timeout still fires on a socket
   that receives dispatches but no ACKs; `zombieReported` resets on traffic; timers cleared on
   destroy (no leaked intervals across reconnects).
6. [x] Changelog "Fixed": "Healthy Gateway connections were closed as zombies every ~45 s".
   Upgrade note: remove `zombieTimeout: Infinity` workarounds.
7. [ ] Consider shipping this alone as **0.2.2** (or a 0.2.1 patch) ahead of the feature steps,
   since it affects every bot on the default options.
8. [ ] ZedBot: drop `zombieTimeout: Infinity` from `src/index.ts` (and any shard entry points)
   once it runs the fixed version; watch one day of logs for `zombie` events.

### Step 8 — Previous state on update and delete events

Today `guildRoleCreate/Update/Delete`, `guildEmojisUpdate` and `guildStickersUpdate` emit raw
payloads after the cache is updated, so a handler cannot see the old value (ZedBot's AntiNuke
captures it from `raw` as a workaround).

1. [ ] Emit the cached structure first and the previous one second on update events:
   `guildRoleUpdate(role, previous | null)`, `channelUpdate(channel, previous | null)`,
   `threadUpdate`, `guildUpdate(guild, previous | null)`, `guildMemberUpdate(member, previous | null)`.
2. [ ] On delete events, emit the removed cached structure when there was one:
   `guildRoleDelete(payload, removed | null)`, `channelDelete(payload, removed | null)`.
3. [ ] `guildEmojisUpdate` / `guildStickersUpdate`: add `previous` (the cached list before).
4. [ ] Only additional trailing arguments — existing handlers keep working. Snapshot the previous
   value by copying fields, since caches may patch in place.
5. [ ] Tests for each event: previous present, previous absent (not cached), delete of uncached.
6. [ ] Docs: events reference lists each event's arguments; changelog "Added".
