# Lunibee 0.2.x — friendlier API, new names, small fixes

**Theme:** make Lunibee pleasant for a real bot (ZedBot is the reference user)
without breaking anything. Every change in the line is additive; renamed APIs
keep their old names as deprecated aliases.

| Release | State | Branch |
|---|---|---|
| 0.2.0 | Released | `master` |
| 0.2.1 | Released (npm) | `master` |
| 0.2.2 | In progress | `dev` |
| 0.2.3 | Reserved for fixes found by early adopters | `dev` |

---

## 0.2.0 — released (record)

Foundation of the line: Gateway split into modules (session, heartbeat,
reconnect, transport, decoder, protocol), REST reservations and Redis store,
bounded message cache, Gateway cache sync for guilds/members/roles/emojis/
stickers/channels/threads/voice states, interaction acknowledgement guard,
follow-ups, modals and collectors. See the changelog on the docs site.

## 0.2.1 — released (record)

- [x] `message.member` with guild-level permissions computed from cached roles (owner gets all)
- [x] Member actions: `kick`, `ban`, `timeout`, `edit`, `addRole`, `removeRole`, `setNickname`
- [x] Merge-style permission overwrites: `permissionOverwrites(id).update({ allow, deny, inherit }, { type, reason })`
- [x] File uploads in `channels.send` / replies (`files`)
- [x] Component and modal collectors
- [x] Prefix-argument parsing: `parsePrefixArgs`, `tokenizeArgs`, `argsFromCommandOptions`
- [x] Builder and typing fixes (`ModalBuilder.addTextInputs`, `showModal(builder)`, `componentsV2Message`)
- [x] `PermissionSet` resolves renamed permission names (e.g. `ManageEmojisAndStickers`)

## 0.2.2 — in progress on `dev`

### Landed

- [x] **Naming convention** (33cb313): builders `CreateX` (`ButtonBuilder` → `CreateButton`),
  `…Style` → `…Type` (`ButtonStyle` → `ButtonType`, `TextInputStyle` → `TextInputType`),
  `…Type` → `…Enum` (`ChannelType` → `ChannelEnum`), new `ActivityEnum`; old names are
  deprecated aliases defined at the bottom of the defining file; `tests/naming.test.ts`.
- [x] **CLI, client-first handlers** (56406de): generated handlers are `handler(client, ...args)`;
  `lunibee create handler <event> [name]` works without prompts; `lunibee sync handlers`
  regenerates `src/handlers/event.ts`.

### Step 1 — Context-menu commands

1. [ ] In `packages/structures/src/interactions.ts`, add `isContextMenuCommand()`,
   `isUserContextMenuCommand()` (`data.type === 2`) and `isMessageContextMenuCommand()`
   (`data.type === 3`), keyed on the application-command `data.type`.
2. [ ] Change `isChatInputCommand()` to be true only for `data.type === 1` (behaviour change —
   note it in the changelog under "Changed" with the one-line fix for callers).
3. [ ] Add getters: `targetId`, `targetUser` (from `resolved.users`), `targetMember` (from
   `resolved.members`, built with the client's `ResourceContext` so actions work),
   `targetMessage` (a `Message` from `resolved.messages`).
4. [ ] The builders already exist (`CreateContextMenuCommand`, `CreateUserCommand`,
   `CreateMessageCommand` in `packages/builders/src/commands.ts`): check they are re-exported
   by `lunibee`, cover contexts and integration types, and document them.
5. [ ] Tests: `tests/context-menu.test.ts` — each guard for types 1/2/3, target getters with and
   without `resolved`, builder `toJSON()`.
6. [ ] Docs: "Context menus" guide page with a user and a message example.

### Step 2 — Client-wide default `allowed_mentions`

1. [ ] Add `ClientOptions.allowedMentions` (Discord shape, e.g. `{ parse: [] }`).
2. [ ] Apply it in one helper (`withDefaultMentions(payload)`) used by channel send/edit,
   message reply, interaction reply/edit/follow-up/update and webhook execute.
3. [ ] A payload's own `allowed_mentions` always wins; `undefined` default changes nothing.
4. [ ] Tests covering each send path with and without an explicit value.
5. [ ] Docs: `ClientOptions` reference + a "Mentions safety" note in the messages guide.

### Step 3 — Export the CDN helpers

1. [ ] Export `CDN_BASE`, `cdnURL()` and `ImageURLOptions` from `@lunibee/structures` and `lunibee`.
2. [ ] Add them to the API-audit allow list; test that the exports exist.
3. [ ] Docs: CDN reference section.

### Step 4 — `reply({ withResponse: true })` returns the message

1. [ ] Pass `?with_response=true` on the interaction callback when requested.
2. [ ] Return a `Message` from `reply()` / `update()` / `deferReply()` / `deferUpdate()` in that
   mode; keep the current return otherwise. Keep `fetchReply()`.
3. [ ] Type overloads so `withResponse: true` returns `Promise<Message>`.
4. [ ] Tests with a mocked REST returning the callback resource.

### Step 5 — `showModal()` accepts `CreateModal.toJSON()` output

1. [ ] Drop the index signature requirement from the raw modal type, or accept `APIModalComponent`.
2. [ ] Test that `showModal(builder)` and `showModal(builder.toJSON())` both type-check and send
   the same body.

### Step 6 — Export component payload types

1. [ ] Re-export `APIComponent`, `APIActionRowChild`, `APIActionRowComponent`, select/option,
   container and text-display payload types from `lunibee`.
2. [ ] API-audit entries; a type-only test file that imports each.

### Step 7 — Message fields AutoMod-style bots need

1. [ ] Add `stickers` (from `sticker_items`), `poll` and `messageSnapshots` (forwards) to
   `Message`, raw API shapes are fine.
2. [ ] Keep them updated on `MESSAGE_UPDATE`.
3. [ ] Tests from recorded payloads; docs on the Message reference page.

### Step 8 — Previous state on update and delete events

Today `guildRoleCreate/Update/Delete`, `guildEmojisUpdate` and `guildStickersUpdate` emit raw
payloads after the cache is updated, so a handler cannot see the old value (ZedBot's AntiNuke
captures it from `raw` as a workaround).

1. [ ] Emit the cached structure first and the previous one second on update events:
   `guildRoleUpdate(role, previous | null)`, `channelUpdate(channel, previous | null)`,
   `threadUpdate`, `guildUpdate(guild, previous | null)`, `guildMemberUpdate(member, previous | null)`.
2. [ ] On delete events, emit the removed cached structure when there was one:
   `guildRoleDelete(payload, removed | null)`, `channelDelete(payload, removed | null)`.
3. [ ] `guildEmojisUpdate` / `guildStickersUpdate`: add `previous` (the cached list before).
4. [ ] Only additional trailing arguments — existing handlers keep working. Snapshot the previous
   value by copying fields, since caches may patch in place.
5. [ ] Tests for each event: previous present, previous absent (not cached), delete of uncached.
6. [ ] Docs: events reference lists each event's arguments; changelog "Added".

### Step 9 — Release 0.2.2

1. [ ] `bun run ci` green; docs site builds; generated API docs valid.
2. [ ] Bump root and workspace versions to 0.2.2; changelog; upgrade notes (naming aliases,

3. [ ] Publish (`lunibee publish`), tag `0.2.2`, GitHub release with the announcement text.
4. [ ] Move ZedBot to `lunibee@0.2.2`; remove its workarounds (raw previous-state capture,

## Release checklist (every 0.2.x release)

- [ ] Root and workspace package versions correct
- [ ] Changelog updated; breaking changes (none expected) documented
- [ ] Upgrade guide updated where behaviour changed
- [ ] Examples use the release version
- [ ] P0/P1 resolved and verified; P2/P3 resolved or tracked
- [ ] `check:deps`, API audit, prettier, typecheck, tests + coverage
- [ ] Production build, DTS build, docs build, generated API docs
- [ ] Final smoke test (examples/basic against a test guild)
