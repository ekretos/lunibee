# Lunibee 0.6.x — packages that install anywhere, voice out of experimental

**Theme:** what 0.4.0 left tracked. The scoped packages publish compiled
JavaScript with declarations, every package declares what it imports, and voice
graduates once it has run against Discord. Bots that install a single
`@lunibee/*` package, or check their code with `tsc`, stop paying for Lunibee's
sources.

**Target:** 0.6.0, then 0.6.x patches. Branch: `dev`.

**Principle:** no API change. Everything here is packaging, CI and lifecycle
hardening; the upgrade guide only lists install-time differences.

---

## Step 1 — Publish JavaScript and declarations (0.4.0 Step 7c, item 3)

1. [ ] Each `@lunibee/*` package publishes `dist/*.js` + `dist/*.d.ts` (built by `bun build` and
   `tsconfig.dts.json`); `exports` points at them, with a `"bun"` condition kept for sources only
   if it measurably helps startup.
2. [ ] A consumer's `tsc` no longer type-checks Lunibee's sources (`skipLibCheck: false` passes on a
   fresh project).
3. [ ] The packages load under Node 22+ (`import "lunibee"` does not throw). Node stays unsupported
   for running a bot (ROADMAP.md, "Not in 1.0"); loading is what tools such as bundlers and test
   runners need.
4. [ ] Tests: `bun run build && bun run build:dts`, then import every package's `dist` from Bun and
   Node in CI.

## Step 2 — Package boundaries

1. [ ] `@lunibee/structures` stops importing types from `@lunibee/core` (it is lower in the layer
   graph): move the shared types to `@lunibee/types`, or declare the dependency if the layer graph
   allows it. `check:deps` fails on an undeclared import, types included.
2. [ ] Every package's `dependencies` lists exactly what its `dist` imports; `check:deps` compares them.
3. [ ] Optional native dependencies (`@snazzah/davey`, Opus, FFmpeg) stay optional: a bot without
   voice installs none of them, checked in CI.

## Step 3 — Install smoke tests

1. [ ] `smoke:install` packs every package (`bun pm pack`), installs each scoped package on its own
   in a temp project, and runs `tsc --noEmit` and a minimal import there.
2. [ ] The same for `lunibee` and for a `lunibee init` project (`--commands slash|message|both`).
3. [ ] Runs on Linux x64, Linux ARM64 and the minimum Bun version (the existing CI matrix).

## Step 4 — Voice graduates from `@experimental` (0.4.0 Step 7c, item 6)

1. [ ] The real-guild smoke test (`smoke:voice`, `voice-smoke.yml`) passes: play a one-minute file,
   pause, resume, leave cleanly; DAVE on and off.
2. [ ] Record that session (Gateway frames and UDP packets, secrets removed) and replay it in CI,
   next to the scripted fake voice server (0.4.0 Step 9, item 1).
3. [ ] Remove the `@experimental` marks from the voice API that the smoke test covers; keep them on
   whatever it does not (receiving, for example), and list both in the docs.

## Step 5 — Decisions and hypotheses left by 0.4.0

1. [ ] Interactions: decide whether an expired interaction token (15 minutes) is refused locally.
   If yes, refuse with a typed error and a margin for clock skew; if no, document why.
   (0.4.0 Step 7c, item 4.)
2. [ ] REST: reproduce or close the hypothesis that an error thrown by a custom store's
   `applyResponse` is not wrapped as a `RESTError` (0.4.0 Step 7c, item 5). A reproduction
   becomes a regression test.
3. [ ] Gateway: put a limit on frames waiting to be inflated under `compress: true` (it drains
   today but nothing bounds it); past the limit, close with 4000 and resume.

## Step 6 — Leak checks in CI

1. [ ] Turn the 0.4.0 memory measurements (collectors, `RequestTracker`, voice UDP, plus Gateway
   reconnects and voice join/leave) into `bun run check:leaks`: N cycles, `Bun.gc(true)`, and
   assertions on heap objects, promises, timers and file descriptors returning to baseline.
2. [ ] Runs nightly and on any change to `ws`, `voice`, `sharding` or `core/collector.ts`.

## Step 7 — Release 0.6.0

1. [ ] Upgrade notes: install-time changes only (dist files, Node loading).
2. [ ] Release checklist below; tag; announcement.
