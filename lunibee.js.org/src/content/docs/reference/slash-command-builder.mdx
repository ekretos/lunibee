import { Tabs, TabItem } from '@astrojs/starlight/components';

`CreateSlashCommand` creates the JSON payload needed to register a slash command with Discord. It does not send any network requests — use the `ApplicationCommandManager` or `client.rest` to register the payload.

## Import

<Tabs>
<TabItem label="TypeScript">
```ts
import { CreateSlashCommand } from "lunibee";
```
</TabItem>
<TabItem label="JavaScript">
```js
import { CreateSlashCommand } from "lunibee";
```
</TabItem>
</Tabs>

## Methods

### `setName(name)`

Sets the command name (1–32 chars, lowercase, no spaces — use hyphens).

<Tabs>
<TabItem label="TypeScript">
```ts
command.setName("ban");
```
</TabItem>
<TabItem label="JavaScript">
```js
command.setName("ban");
```
</TabItem>
</Tabs>

### `setDescription(description)`

Sets the command description (1–100 characters).

<Tabs>
<TabItem label="TypeScript">
```ts
command.setDescription("Bans a member from the server.");
```
</TabItem>
<TabItem label="JavaScript">
```js
command.setDescription("Bans a member from the server.");
```
</TabItem>
</Tabs>

### `setDefaultMemberPermissions(permissions)`

Sets the default member permissions required to see and use the command.

<Tabs>
<TabItem label="TypeScript">
```ts
import { Permission } from "lunibee";
command.setDefaultMemberPermissions(Permission.banMembers);
```
</TabItem>
<TabItem label="JavaScript">
```js
import { Permission } from "lunibee";
command.setDefaultMemberPermissions(Permission.banMembers);
```
</TabItem>
</Tabs>

### `setContexts(...contexts)`

Where the command can be used: `0` guilds, `1` the bot's DMs, `2` other DMs. Any other value throws a `RangeError`.

<Tabs>
<TabItem label="TypeScript">
```ts
command.setContexts(0); // guilds only
```
</TabItem>
<TabItem label="JavaScript">
```js
command.setContexts(0); // guilds only
```
</TabItem>
</Tabs>

### `setDMPermission(allowed)` (deprecated)

Discord deprecated `dm_permission`. Use `setContexts()` instead: `setDMPermission(false)` becomes `setContexts(0)`, and, for a guild-installed bot, `setDMPermission(true)` becomes `setContexts(0, 1)`. Still works in 0.2.x; removed in 0.3.1.

## Option Builders

Each option type has a corresponding method. All return `this`.

| Method | Option Type |
|---|---|
| `addStringOption(fn)` | Text input |
| `addIntegerOption(fn)` | Whole number |
| `addNumberOption(fn)` | Float |
| `addBooleanOption(fn)` | True/false |
| `addUserOption(fn)` | Discord user picker |
| `addChannelOption(fn)` | Channel picker |
| `addRoleOption(fn)` | Role picker |
| `addMentionableOption(fn)` | User or role picker |
| `addAttachmentOption(fn)` | File attachment |
| `addSubcommand(fn)` | Subcommand |
| `addSubcommandGroup(fn)` | Subcommand group |

### Option method signature

<Tabs>
<TabItem label="TypeScript">

  option
    .setName("reason")

### `toJSON()`

Returns the Discord API-compatible command payload object.

## Option builder classes

Each `addXOption(fn)` callback receives one of these classes. They can also be built on their own and passed to `addXOption(option)`.

| Class | Option type | Extra methods |
|---|---|---|
| `CreateStringOption` | 3 | `addChoices({ name, value })`, `setMinLength`, `setMaxLength`, `setAutocomplete` |
| `CreateIntegerOption` | 4 | `addChoices`, `setMinValue`, `setMaxValue`, `setAutocomplete` (integers only) |
| `CreateNumberOption` | 10 | `addChoices`, `setMinValue`, `setMaxValue`, `setAutocomplete` |
| `CreateBooleanOption` | 5 | — |
| `CreateUserOption` | 6 | — |
| `CreateChannelOption` | 7 | `addChannelTypes(...types)` |
| `CreateRoleOption` | 8 | — |
| `CreateMentionableOption` | 9 | — |
| `CreateAttachmentOption` | 11 | — |

All of them have `setName`, `setDescription` and `setRequired`. Choices must be strings of 1-100 characters or finite numbers (at most 25), an option with choices cannot use autocomplete, and `setMinValue` / `setMaxValue` throw a `RangeError` if the minimum would exceed the maximum.

## Subcommands

`addSubcommand(fn)` adds a `CreateSubcommand` (type 1), which takes the same `addXOption` methods. `addSubcommandGroup(fn)` adds a `CreateSubcommandGroup` (type 2), whose only children are subcommands.

```ts
const config = new CreateSlashCommand()
  .setName("config")
  .setDescription("Bot settings")
  .addSubcommandGroup((group) =>
    group
      .setName("prefix")
      .setDescription("Prefix settings")
      .addSubcommand((sub) =>
        sub
          .setName("set")
          .setDescription("Change the prefix")
          .addStringOption((o) => o.setName("value").setDescription("New prefix").setRequired(true)),
      ),
  );
```

In the handler, `interaction.options.getSubcommandGroup()` and `getSubcommand()` tell you which one ran.
