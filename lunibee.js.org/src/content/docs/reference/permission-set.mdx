---
title: PermissionSet
description: BigInt-backed permission bitfield checker. Supports named permission keys, raw bigints, and immutable set operations.
---

import { Tabs, TabItem } from '@astrojs/starlight/components';

`PermissionSet` (with a `PermissionsBitField` subclass, which adds the static `Flags` and `All` constants) provides named permission checks against Discord's 64-bit permission bitfield. Sets are immutable.

## Import

<Tabs>
<TabItem label="TypeScript">
```ts
import { PermissionSet, Permission } from "lunibee";
// Alias:
import { PermissionsBitField } from "lunibee";
```
</TabItem>
<TabItem label="JavaScript">
```js
import { PermissionSet, Permission } from "lunibee";
// Alias:
import { PermissionsBitField } from "lunibee";
```
</TabItem>
</Tabs>

## Constructor

<Tabs>
<TabItem label="TypeScript">
```ts
new PermissionSet(value: PermissionResolvable = 0n)
```
</TabItem>
<TabItem label="JavaScript">
```js
new PermissionSet(value = 0n)
```
</TabItem>
</Tabs>

`value` is a bitfield (bigint, number or decimal string), a permission name, another set, or an array of these. A negative value throws a `RangeError`, anything else unparseable a `TypeError`.

<Tabs>
<TabItem label="TypeScript">
```ts
const perms = new PermissionSet(member.permissions.bitfield);
```
</TabItem>
<TabItem label="JavaScript">
```js
const perms = new PermissionSet(member.permissions.bitfield);
```
</TabItem>
</Tabs>

## Properties

| Property | Type | Description |
|---|---|---|
| `bitfield` | `bigint` | The raw bitfield as a BigInt. |
| `kickMembers`, `banMembers`, `administrator`, … | `boolean` | One camelCase getter per permission, including `setVoiceChannelStatus`, `pinMessages` and `bypassSlowmode`; true when the bit is set. |

## Methods

### `has(...permissions)`

Returns `true` only if **all** of the given permissions are present. Accepts a `Permission` constant, a `bigint`, a number, a `PermissionSet`, an array, or a camelCase/PascalCase permission name string.

<Tabs>
<TabItem label="TypeScript">
```ts
if (member.permissions.has(Permission.manageMessages)) {
  // allowed
}

// Also works with string keys:
if (member.permissions.has("manageMessages")) {
  // allowed
}
```
</TabItem>
<TabItem label="JavaScript">
```js
if (member.permissions.has(Permission.manageMessages)) {
  // allowed
}

// Also works with string keys:
if (member.permissions.has("manageMessages")) {
  // allowed
}
```
</TabItem>
</Tabs>

### `any(...permissions)`

Returns `true` if **at least one** of the given permissions is present.

<Tabs>
<TabItem label="TypeScript">
```ts
if (member.permissions.any(Permission.banMembers, Permission.kickMembers)) {
  console.log("Can ban or kick.");
}
```
</TabItem>
<TabItem label="JavaScript">
```js
if (member.permissions.any(Permission.banMembers, Permission.kickMembers)) {
  console.log("Can ban or kick.");
}
```
</TabItem>
</Tabs>

For Administrator, use the `administrator` getter (`member.permissions.administrator`)
or `has(Permission.administrator)`. `has()` does not treat Administrator as implying
other permissions.

### `add(...permissions)`

Returns a **new** `PermissionSet` with the given permissions added (immutable).

<Tabs>
<TabItem label="TypeScript">
```ts
const updated = perms.add(Permission.sendMessages, Permission.readMessageHistory);
```
</TabItem>
<TabItem label="JavaScript">
```js
const updated = perms.add(Permission.sendMessages, Permission.readMessageHistory);
```
</TabItem>
</Tabs>

### `remove(...permissions)`

Returns a **new** `PermissionSet` with the given permissions removed (immutable).

<Tabs>
<TabItem label="TypeScript">
```ts
const restricted = perms.remove(Permission.manageMessages);
```
</TabItem>
<TabItem label="JavaScript">
```js
const restricted = perms.remove(Permission.manageMessages);
```
</TabItem>
</Tabs>

### `toArray()`

Returns an array of all active permission names.

<Tabs>
<TabItem label="TypeScript">
```ts
const permNames = member.permissions.toArray();
// → ["viewChannel", "sendMessages", "readMessageHistory", ...]
```
</TabItem>
<TabItem label="JavaScript">
```js
const permNames = member.permissions.toArray();
// → ["viewChannel", "sendMessages", "readMessageHistory", ...]
```
</TabItem>
</Tabs>

### `equals(other)`

Whether another `PermissionSet` or raw bitfield (bigint, number or string) has the same bits.

### `toString()`

Returns the bitfield as a decimal string (useful for API payloads).

<Tabs>
<TabItem label="TypeScript">
```ts
const payload = { permissions: member.permissions.toString() };
```
</TabItem>
<TabItem label="JavaScript">
```js
const payload = { permissions: member.permissions.toString() };
```
</TabItem>
</Tabs>

## Examples

**Permission gate in a command**

<Tabs>
<TabItem label="TypeScript">
```ts
import { Permission } from "lunibee";

client.on("interactionCreate", async (interaction) => {
  if (!interaction.isChatInputCommand() || interaction.commandName !== "ban") return;
  if (!interaction.member?.permissions.has(Permission.banMembers)) {
    return interaction.reply({ content: "You need the Ban Members permission.", ephemeral: true });
  }
  // proceed with ban...
});
```
</TabItem>

## 0.2.0 Additions

- `missing(...permissions)` returns the requested permission names the set lacks.
- New flags: `setVoiceChannelStatus` (bit 48), `pinMessages` (51), `bypassSlowmode` (52).
- `computePermissions({ guildId, ownerId, memberId, memberRoleIds, roles, overwrites })`
  resolves effective permissions in Discord's order (base from `@everyone` and the member's roles, then the
  `@everyone` overwrite, role overwrites, member overwrite); owners and administrators get every permission.
  With `timedOutUntil` in the future, the member keeps only `viewChannel` and `readMessageHistory`.

```ts
const perms = computePermissions({ guildId, ownerId, memberId, memberRoleIds, roles, overwrites });
perms.missing("sendMessages", "embedLinks");
```

## 0.2.1 Additions

Permission names Discord has since renamed still resolve: `ManageEmojisAndStickers` and `ManageEmojis` (now `ManageGuildExpressions`), and `UseSlashCommands` (now `UseApplicationCommands`).

`GuildMember.permissions` is computed from the cached roles for members that did not come with permissions from Discord (see [GuildMember](/reference/guild-member/)).

## `PermissionFlagsBits`

Discord's permission bits as `bigint`s: `PermissionFlagsBits.BanMembers`, `PermissionFlagsBits.ManageMessages` and so on. It is the same object as `Permissions`, and every method on this page accepts its values.

```ts
member.permissions.has(PermissionFlagsBits.BanMembers);
```
